# 架构说明

这是依赖静态 H5 和本地数据的单伙伴生活框架。Node 服务仅用于静态文件与可选模型代理。没有公共账号、云存档或必须调用模型的日常逻辑。

## 数据关系

```text
outfits：独立装扮形象、描述 ─┐
                            ├─ 家具动作的装扮变体 → 若干完整互动帧
furniture：独立空家具、画布 ─┘
     ↓
scenes[].placements：家具实例的位置、比例、图层
     ↓
state.activity：全局唯一活动地点、家具实例、动作与时间
```

装扮选择只修改 `selectedOutfitId`。家具定义只描述这类家具的空图、画布及支持的活动，实例决定它放在哪里。互动素材通过家具、动作、装扮三个 ID 关联。

`viewSceneId` 决定显示的生活场景；`activity.sceneId` 记录伙伴实际活动的位置。家装中选择已拥有的地点时，整套家具布局一起转移到新背景，保留活动的动作和时间。查看相册、出发地图不改变伙伴的活动。一个实例显示完整互动图时，其他所有实例显示空家具。旅行期间全部显示空家具。

## 模块

- `core/itinerary.js`：随机旅行与休息时长、1–3节点计划、统一图文提示词、定时成对投递、静默本地回退。
- `core/travel.js`：均匀随机目的地、API配置判断、地点默认图索引、定期金币来信与离线去重。
- `core/economy.js`：9999起始金币、价格、购买、拥有状态与家具库存；扣款和入库同步完成。
- `core/pack.js`：素材结构、路径、尺寸、基础回退与引用校验。
- `core/engine.js`：创建／恢复存档、家具移动、活动选择、装扮回退、逐帧计时、旅行计划和唯一结算。
- `core/frame-buffer.js`：异步帧切换。只有最新请求可以提交，失败保留上一帧，销毁后禁止迟到结果写回。
- `images.js`：图片加载与解码缓存。
- `scene.js`：场景平移缩放、家具布置、准备并切换完整互动帧。
- `main.js`、`views.js`：用户操作、简洁主页面、装扮／行囊、素材调节面板。
- `storage.js`：IndexedDB、图片校验、素材 ZIP、完整存档 ZIP。
- `ai.js`：一次文字旅行规划、可选的一次图片生成。
- `webmcp.js`：使用同一套规则暴露读取状态、调整家具位置和旅行节奏；不主动调用付费模型。

## 不闪烁的图片切换

旧实现用 `innerHTML` 删除显示中的精灵，未等待下一张解码，存在短暂空白的风险。现实现预取当前动作的图片，并对即将使用的图片执行加载与解码，完成后才原子替换内容。加载失败不清空旧帧；快速切换装扮时，迟到的旧请求不能盖回新选择。

打开行囊、设置等面板时复用原场景节点。调整同一件家具的位置与比例也复用原图层。场景销毁会注销监听、停止计时并使未完成的换帧请求失效。

运行时仍可读取已有图集的 `rect`；新示例使用每帧一个独立 PNG，不使用网格图集或逐帧位移补偿。

## 时间与随机活动

日常调度从已经放置的、具备动作的家具实例中随机选择，停留数分钟。每段活动内部按各帧的 `duration` 缓慢播放。没有走路、跑步、插值位移或寻路。进入家装时暂停随机选活动，退出后恢复。页面关闭期间不会补演动作或新建付费请求。

活动解析先查所选装扮，再查基础装扮。基础装扮是每个动作的必需版本，因此缺失可选素材不需要改变用户的外观选择。

## 自动旅行与统一图文行程

默认自动出门。每次出发随机选择60–180分钟的旅行，回来随机休息5–15分钟；范围仅在开发者设置调整。普通出发弹窗不提供时间输入，预计归来和后续出发时间只在开发者区域显示。

出发前确定目的地、整套外观、随身物品、总时长、1–3个节点及相对投递时间。节点计划和金币规则随旅程保存，不在每次 tick 或页面刷新时重新随机。免费目的地随机，花金币才指定；指定费用在真正开始时扣除。

完整 AI 模式只调用一次文字 API，生成整段故事、统一视觉规则，以及每个节点的地点、活动、来信和构图。每个生图提示词由共同故事、固定装备与当前节点字段组合，强制文字与图画描述同一事件。出发时的穿搭参考图另存为本地媒体快照，所有节点沿用，后续换装不会改写旧行程。

节点到时进入照片队列，图片串行生成。AI 文案与对应照片一起发布，未成功生成的照片不会提前配上精确的 AI 文案。无 AI 时按时间发布本地文案和地区默认照片。相册可以在旅行尚未结束时收到节点来信；到访次数仍按完成旅程计一次。

任一 AI 规划失败，整程使用预先准备的本地计划；图片失败或请求被中断，已经发布的来信保留，本程未发布节点静默切回本地文案和默认图。普通页面不显示 API 错误或自动重试。原因只保留在开发者记录。配置可用 API 后，游戏不设每日调用次数上限；调用次数只用于记录，已有节点不会重复投递，图片请求仍串行执行。

关闭页面时不在后台调用模型；再次打开会补齐已开始旅程的到期节点和金币。已过休息时间时，页面恢复运行后可以自动安排下一程，不补造离线期间的无限新旅程。所有节点照片和参考图都包含在完整存档的媒体备份中。

## 保存与迁移

继续使用既有 IndexedDB 数据库，存档内容版本为 2。旧版升级先保存原数据快照，再迁移昵称、旧照片、旅程和访问记录；旧版人物位置、挂点和分层装备配置不再执行。旧版存档 ZIP 也可以迁移历史记录。

外部存档导入保留当前设备 API 配置，暂停自动出发。密钥不保存在素材、进度或备份中。页面密钥仅在内存；代理可读取部署者自己的环境变量。

启动时会识别仍引用旧图集的内置示例配置，先保存原配置和进度快照，再自动升级到独立帧；不重置装扮选择、家具布置、相机或照片。用户自带的图片、定制互动与发生 ID 冲突的资源不自动覆盖。旧图集 URL 继续作为已打开页面与旧包的兼容资源，新的示例素材 ZIP 只包含当前清单声明的图片。

“更新内置示例素材”先备份当前素材和进度，保留旅行照片，并可通过素材面板撤销。整包导入则明确提示开启新生活，先提供备份入口。

## 本地代理

服务默认监听回环地址，验证 Host、Origin 和运行时令牌。转发目标校验协议、域名、DNS 地址及请求大小；默认拒绝内网目标和重定向。公网监听必须由部署者明确配置令牌和供应商白名单。本交付只提供本地源码与示例素材，不发布公共服务。

## 验证重点

测试覆盖唯一活动地点、场景浏览独立性、装扮回退、慢帧边界、旅行离线结算、存档迁移、延迟加载与解码失败、快速切换后旧请求失效、素材输入校验和本地代理。真实模型调用取决于使用者供应商，模拟接口测试不等于付费模型已完成联调。


## 六个用户入口

主导航为装备、出发、相册、家装、商店、设置。装备只展示已拥有的整套装扮和随身物品；出发直接打开交互地图，在选中目的地后弹出随机或金币指定的旅行配置。设置默认只显示名字，素材、API和调试功能集中在折叠的开发者设置里。

`state.economy` 保存金币和已拥有的商品。首次启用补上9999金币与原来已使用的物品，后续刷新不会重复发放。家具多件摆放需要对应库存，收回后数量回到仓库，最后一件受规则层保护。地点购买与世界旅行记录互不关联。

素材缩略图使用保持宽高比的视口显示，固定大小的卡片不会拉伸图片。家具显示宽高由同一个缩放值和素材原比例计算；拖动只更新坐标，并禁止浏览器原生图片拖拽。


## 20种旅行照片风格

普通设置提供20种图片风格与“素材包默认”。`settings.photoStyleId` 保存选择；出发时把 `id/name/prompt` 三个纯文字字段固定在 `itinerary.photoStyle`，随后节点沿用，不被中途设置修改。

`app/core/photo-styles.js` 只含风格文字，`app/photo-style-previews.js` 单独包含前端图片路径。`photo-styles/previews/` 的20张图片仅供设置页浏览，不进入素材包 assets、存档媒体、行程上下文或任何模型参考图参数。图片API的唯一参考仍然是出发时冻结的角色穿搭图。

文字取自已有风格作品的 style 字段，去除固定雪山、湖泊、落日等原始对比图的构图限制。用户选择的风格替代素材包的绘画媒介，并统一作用于角色和背景，衣服的设计与识别特征保留。无API时的默认照片不被改画。

## 本地模型配置与时间模拟

可在 `.env` 设置 `OPENROUTER_API_KEY` 和对应的 Base URL、模型 ID；密钥只由服务端使用，不进入资源包或存档。默认 OpenRouter 配置选择 `openai/gpt-5.6-luna` 与 `openai/gpt-image-2.5-sunburst`。文字使用 Chat Completions，图片使用 `/api/v1/images` JSON，角色参考放在 `input_references`；照片风格预览不参与上传。首次读取新的本地配置版本会打开开发者设置，保存设置本身不请求模型。

开发者设置中的“推进时间”支持固定分钟、自定义分钟和下一事件。统一游戏时钟使用真实时间加存档中的 `simulationOffsetMs`，旅行、动作、来信与归来按同一时钟结算。推进后继续使用正常的自动旅行流程，配置模型时会产生正常 API 请求。每日 API 限额仍按真实日期，模拟时间不能绕过限额。累计推进保存在本地存档，刷新不会丢失。`?developer=1` 可直接打开开发者设置。

内置大型素材按使用逐步缓存，安装应用只预取启动场景、基础装扮和第一个家具的基础动作，避免首开下载全部动作矩阵。

## 大型素材包

完整矩阵采用保持可见RGBA像素完全一致的无损WebP，原始PNG在制作输出中保留。浏览器通过core/archive.js分块读取ZIP，先校验中央目录及大小限制，再逐项解压为Blob，并校验CRC；导出逐项读取素材，避免先构造一个完整的字节数组副本。ZIP解压上限512MB，单文件30MB、1500个文件的限制保留。源码打包同样使用流式写入，普通发行包排除私密.env。
