# 给 AI 的素材制作说明

当前发布版本已获用户批准使用Q90。下面的无损流程用于制作母稿，发布时再从母稿单次编码Q90；不缩放、不裁切，alpha无损，RGB有损。步骤与原稿位置见 [Q90发布记录](Q90-RELEASE.md)。

先读取 `ASSET-PACK-SPEC.md`、`pack.schema.json` 和最新示例的 `pack.json`。本框架的装扮、家具是独立资源，互动帧只描述二者的一种组合。

## 可直接交给创作 AI 的任务

> 为我制作原创的 H5 生活素材包。先独立生成角色各套装扮的形象图，以及不含人物的空家具。再以同一张空家具和人物形象为参考，逐张生成家具互动帧。每次只输出一张、一个姿态，禁止把不同动作一起生成成 2×2 或其他网格。后续帧只编辑上一张选定帧中需要变化的局部，例如一页书或杯子与手。保持完整画布、相机、家具尺寸、家具位置及不动区域一致，不重新构图。批量生成使用纯均匀洋红背景，随后用本地算法增加真实透明通道；不要反复请求模型抠图。最终检查 alpha，不接受画出来的棋盘背景。互动图中的人物、衣服、家具、道具和接触遮挡一次画好。为每件家具提供基础装扮动作，可再适配其他整套装扮。按真实图片尺寸写 pack.json，并记录每次选定图片的提示词和引用。地图沿用指定的中国来源标准地图，不生成政治边界。

## 生成顺序

1. **角色与装扮**：固定脸部、体型、耳朵、尾巴、色彩与绘画方式。默认外观和每套装扮各生成一张独立人物图，不带家具。原稿可用纯洋红背景，成品由算法处理为透明。衣服是一套完整外观，不拆成可组合的帽子围巾零件。
2. **空家具**：只生成一件家具，预留人物空间。记录实际画布、家具外轮廓和地面接触点。把这张文件作为后续互动的统一底稿。
3. **主姿态 A**：参考空家具和人物图，加入人物与道具。人物确实坐进软垫，扶手正确遮住身体局部，手握住书或杯子，画好接触阴影。
4. **微动作 B**：以通过检查的 A 帧为编辑目标，只翻一页书或轻抬杯子。保留家具、身体大轮廓、视角和画布。一次只做这一帧。
5. **其他动作**：依然参考已选定的完整底稿，局部改变道具与手部姿势。先做 A，再局部编辑 B。
6. **其他装扮**：使用相同家具参考，替换成独立装扮设定中的衣服。再以这套装扮的 A 帧生成 B，避免跨帧重画整件家具。
7. **核对与导出**：逐张验证真实尺寸与透明度。对比椅背、扶手、椅脚等不动位置。明显位移或形变的帧重做，不假设模型自动做到像素级锁定。之后写素材配置、验证并输出 ZIP。

## 单帧提示词模板

```text
Edit target: the approved single full-canvas furniture-and-character image.
Supporting reference: the standalone outfit image, only for clothing/identity.
Change only: [one page curling / hands lifting the cup very slightly].
Preserve: exact canvas dimensions, camera, furniture position, furniture size,
chair feet baseline, armrests, cushion, body/head position, lighting and style.
One image, one pose. No atlas, grid, panels, comparisons or contact sheet.
Uniform solid magenta #FF00FF backdrop, no texture or gradient.
Keep this key color out of the subject. A local algorithm will add alpha.
Keep correct hand/prop contact and clothing occlusion. No text or watermark.
```

批量任务中，生成代理只负责一次出图，主任务统一使用本地算法抠图与复核。若原生透明一次成功，可以保留其alpha；不要为了透明反复重画主体。算法也要保护白色毛发、帽子和坐垫，不能简单删除所有近白色像素。

## 慢动作配置

```json
{"frames": [
  {"asset": "winter-read-a", "duration": 4000},
  {"asset": "winter-read-b", "duration": 1200}
]}
```

不必生成 GIF。独立 PNG 配合播放时长可以组成缓慢变化；只有一张时也能作为静态动作。日常播放不调用模型。

## 旅行参考

旅行生图使用所选装扮的独立人物图，并附带外观描述、随身物品和目的地提示词。不要把阅读椅或整张动作图集作为衣橱参考。旧回忆保留原图；新旅行图片保存为新记录。

## 交付检查

- 装扮图只有人物；空家具图没有人物；互动图的两者关系自然。
- 每个文件只有一帧，尺寸与统一底稿一致，主体没有裁切。
- alpha 真实有效，淡色主体未被误删，没有棋盘残留。
- 静止家具位置与轮廓稳定；轻微笔触变化需要如实记录，不能声称绝对无偏移。
- 每个家具动作有基础装扮版本；其他版本缺失时回退可用。
- 全部实际支持的组合逐组预览，检查循环边界、装扮切换、家具移动和旅行空置。
- 素材包可导入、再导出；所有图片都在包内；列明原创素材和第三方资料来源。

示例最终提示词及实际检查见包内 `PROMPTS.md` 与 `ASSET-METADATA.json`。

新增装扮、随身物品、家具和生活地点时，可在对应定义上填写 `price`。价格不放在图片资源的 `assets` 条目上。默认礼包只有基础装扮、初始地点和起始家具，其余资源供商店购买。

未来制作地区默认图库时，每个有效国家与中国省级地区各提供一张完整图片，写入 `destinationPhotos` 映射。当前只接入索引，并未开始生成。文字 API 的提示词必须围绕已经随机抽取或用金币指定的目的地，不能根据装备或用户叮嘱更换地点。


## 旅行参考图与提示词

默认 Images Edits 接口使用出发时穿着整套服装的独立角色图作为固定参考。每个节点提示词附上整个故事与统一画风，再限定当前地点、动作、场景和对应来信。要求保持角色与服装，匹配透视、比例、光照、投影、接触阴影及遮挡，让角色自然进入场景。每次只画本节点的一张照片，不生成拼贴或图集。

行程生成只做一次文字请求。照片按节点串行调用，图文成对发布；规划或生图失败使用本地备用计划，不临时拼凑互相矛盾的独立文案。


## 选择照片风格

设置页20张风格样例只用于给用户看效果，不能作为参考图上传。生图时只附角色穿搭参考图，把所选风格的纯文字描述加入整段行程及各节点Prompt。不要复制样例完整Prompt中的固定构图，也不要要求复制样例里的雪山、湖泊或落日；实际地点与事件由行程决定。风格须同时作用于角色和环境。

## 批量制作的本地抠图流程

目前批量制作采用：一次原始生图 → 本地算法增加alpha → 复核 → 无损WebP发布，保留全部原始PNG用于编辑。`scripts/cutout-assets.py` 使用Pillow、NumPy、SciPy，支持中性棋盘背景和纯洋红背景；它保持原始画布与RGB色值。白色、蓝色、胡须和家具间隙需要复核。脚本不是任意复杂照片的通用分割器。用户已经确认对比样张，授权本项目采用算法抠图。

尚未开始的新A帧可要求完全均匀的 `#FF00FF` 背景，不加纹理、渐变、阴影，不让主体含相同洋红色。B沿用自己的A底色，只改局部动作。制作代理负责一次出图，主任务统一批量处理alpha及修补失败稿。

`process-expanded-assets.py` 处理新增原稿并缓存源文件校验和；`review-expanded-assets.py` 生成基础动作对照；`integrate-expanded-assets.py` 仅接入processed/approved.json中已复核的组合。资源的可见RGBA在无损WebP编码前后必须完全相同。最终源PNG保存在output中。运行游戏不需要Python；这套制作脚本需要Pillow、NumPy和SciPy。

对整体上下偏移使用现有registration字段将实测地面锚点映射到空家具的地面位置，宽高比例一致。局部缺失、拉伸或家具形状改变仍需修复原图，不能靠坐标伪装通过。

## 数量与并行规则

总互动帧数等于每个家具实际支持的动作帧数之和，再按各动作适配的外观数累加。当前示例10家具×2动作×10装扮×2帧=400。不同家具、不同装扮A可以并行，同一个B必须等待它自己的A完成与检查。第一图为姿态和家具母版，第二图仅为服饰参考；不要用一套新衣继续串改下一套，以免误差累积。帽子完整并留出少量上边距。

动作禁止2×2或其他网格；随身物品静态库存图标允许规则图集，但应按实测尺寸写rect，确保内容不跨格。

## 生活场景背景

当前示例共20个地点。每个背景独立生成，横向1536×1024，轻微俯视、三分之四正面；主要装饰集中远处和侧缘，前下方保留约一半至六成的平整连续地面。背景不画角色或可移动家具。建筑附属细节与极少边缘装饰可保留，但不能占用中央摆放区域。实际提示词见包内SCENE-PROMPTS.md。

新地点写入scenes，background指向完整场景asset，width/height保持实际尺寸，placements默认为空，price为金币售价。沿用统一家具布置和等比场景相机；不要给每个新地点附送一整套家具。scripts/integrate-expanded-scenes.py接入根复核过的originals及approved.json，并校验无损编码完整像素一致。
